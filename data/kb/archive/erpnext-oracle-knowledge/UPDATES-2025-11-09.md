## Key Learnings Documented

### 1. CSS Scoping

**Problem:**
```python
# hooks.py
app_include_css = "/assets/plant_floor_management/css/shop_floor.css"
```

**Impact:**
- Broke ALL ERPNext forms site-wide
- Fields oversized (48px min-height applied globally)
- Buttons too large everywhere
- Standard pages unusable

**Solution:**
1. Remove from hooks.py
2. Load CSS with `frappe.require()` on page load
3. Scope ALL selectors to `.page-{name}`

**Defense in Depth:**
- Method 1: Page-level loading (prevents loading when not needed)
- Method 2: Scoped selectors (prevents affecting other pages even if loaded)
- Method 3: Both (belt and suspenders approach)

All examples are from **production code** (Plant Floor Management app):

### 1. Tree View with API Integration

```javascript
this.tree = new frappe.ui.Tree({
    parent: $(this.page.main),
    label: __('Work Orders'),
    method: 'plant_floor_management.plant_floor_management.api.get_tree_nodes',
    on_click: (node) => {
        if (!node.expandable) {
            this.show_quick_entry(node.data.value);
        }
    }

```

### 2. Quick Entry Dialog with Duplicate Prevention

```javascript
let d = new frappe.ui.Dialog({
    title: __('Complete Job Card'),
    fields: [
        {fieldname: 'completed_qty', fieldtype: 'Int', reqd: 1},
        {fieldname: 'employee', fieldtype: 'Link', options: 'Employee'},
        {fieldname: 'reject_qty', fieldtype: 'Int', default: 0}
    ],
    primary_action: (values) => {
        d.get_primary_btn().prop('disabled', true);  // Prevent duplicates

        frappe.call({
            method: 'plant_floor_management.plant_floor_management.api.complete_job_card',
            args: { job_card_name: job_card.name, ...values },
            callback: (r) => {
                if (r.message && r.message.success) {
                    d.hide();
                    this.refresh();
                }
            },
            error: () => {
                d.get_primary_btn().prop('disabled', false);
            }
        });
    }
});
```

### 3. Server API with Permissions and Type Conversion

```python
@frappe.whitelist()
def complete_job_card(job_card_name, completed_qty, employee, reject_qty=0):
    """Complete a Job Card with quantity and employee information"""
    try:
        # Type conversion (JavaScript sends strings)
        completed_qty = int(completed_qty) if completed_qty else 0
        reject_qty = int(reject_qty) if reject_qty else 0

        # Validation
        if completed_qty <= 0:
            frappe.throw(_("Completed quantity must be greater than 0"))

        # Get Job Card document
        job_card = frappe.get_doc('Job Card', job_card_name)

        # Check permissions
        if not frappe.has_permission('Job Card', 'write', job_card):
            frappe.throw(_('No permission'), frappe.PermissionError)

        # Process...
        job_card.total_completed_qty += completed_qty
        job_card.save()

        return {
            'success': True,
            'message': _('Job Card updated successfully'),
            'data': job_card.as_dict()
        }

    except Exception as e:
        frappe.log_error(title='Complete Job Card Error', message=str(e))
        return {'success': False, 'message': str(e)}
```

## Lessons for Future Development

### 1. Always Test Impact

When adding ANY CSS:
1. Check if it affects other pages
2. Test standard ERPNext forms
3. Hard refresh browser (Ctrl+F5)
4. Test on clean browser profile

### 2. Defense in Depth

For critical features like CSS:
- Multiple layers of protection
- Page-level loading + scoped selectors
- Clear documentation
- Automated tests (future)

### 3. Document While Building

Best time to document is **during** development:
- Fresh memory of problems encountered
- Real code examples available
- Can capture "gotchas" immediately
- More authentic examples

- Actual production code
